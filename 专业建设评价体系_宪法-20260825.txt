专业建设质量诊断系统——宪法文件



用户端总原则

本文件是用户端核心文件，面向使用者，回答三个问题：
• 产品是什么：专业建设质量诊断、建设指导与评价验收的一站式平台——不只告诉你问题在哪，还帮你改、帮你验收改得怎么样
• 用户需要做什么：填模板、看报告、按指引做改进
• 能得到什么：一套从诊断到建设到验收的完整闭环——清晰的问题定位、可操作的改进方案、可量化的验收结果

用户端文件不暴露内部实现细节。所有"系统怎么设计、怎么校验、怎么分层分析"的内容，统一放在开发端文件（设计决策备忘录及各步骤内部研讨文件）中。



一、产品定位

1.1 核心定位：专业建设评价中台

不做系统的替代者，做系统之上的评价层。

不碰各校的日常教务运转，只在"专业建设评价"这个垂直场景上，建一个独立的数据入口和评价引擎。

1.2 两层数据运作

第一层：评价专用数据——教师通过模板直接录入

评价体系中有大量数据，本来就不是教务系统里现成的：产业白皮书、增强版课程大纲、课程-产业链映射矩阵、达成度报告、综合验证课程设计等。我们的平台为这些数据提供标准化入口——教师填模板，系统自动校验、自动评分、自动出诊断报告。

第二层：行为数据——轻量对接，能采多少采多少

出勤率、作业提交率、实验开出率、教材出版年份、就业率、横向课题等，来自现有教务系统和课程平台。最简单的做法：每学期导出一份标准格式Excel上传即可。初期甚至不需要——手动填写关键数据，平台先跑起来。

1.3 为什么选择这条路

因为我们帮你解决的，是你本来就要做、但一直做不好的三件事：

对学校——帮你把专业建设的根本问题想明白。 新增什么专业、保留什么专业、撤销什么专业——过去往往看条件办事，缺少扎实的依据。我们帮你基于社会需求、产业趋势、学校基因，找到每个专业设置背后的真正依据。同时帮你厘清就业质量、办学质量和办学特色这三本账——这些问题你一直被追问，但缺乏系统性的数据支撑。

对教务处和学院——帮你把培养的全过程看清楚。 培养方案到底科不科学？执行过程中有没有走样？最终结果怎么样？发现差距后怎么有效改进和提升？这些中层最头疼的闭环问题，我们帮你用数据串起来——标准我们来定，数据我们来跑，你只需要看结论、做决策。

对教师——帮你把"提升教学质量"落到实处。 教学质量到底意味着什么？抓手在哪里？很多老师把提升教学质量等同于课堂活跃度、学生评教分数、期末卷面成绩——但这些远远不够。我们帮你理清教学质量真正的内涵和抓手，然后告诉你：你要做什么、怎么做、做成什么样算好。方向我们给、方法我们给、模板我们给、范本我们给——让你尽可能简单地做到位。



二、核心架构

2.1 运行机制

整个评价体系的核心运行机制是AI主导。从数据采集、到诊断分析、到改进建议、到过程追踪、到结果验收，AI是主力，专家只在AI标记为"需要人工判断"的极少数场景下介入。

核心结论：17项指标中，71%可完全由AI自动完成，29%由AI主导+人工确认，无需专家介入。

系统的技术内核由三个AI引擎构成：
• AI数据采集引擎：从各类数据源自动采集、校验、结构化评价所需数据
• AI诊断引擎：基于采集数据，沿依赖关系图自动诊断，输出结论和建议
• AI追踪引擎：持续监控改进过程，自动验证改进效果

三层分工

• 教师操作层极简：教师是专业建设的执行者，不是评价体系的设计者。教师只需要提供原始事实：培养目标文本、课程清单、考核方式、成绩数据——这些只有教师才知道。
• AI处理层黑箱：所有分析、推导、校验、诊断都在后台自动完成。技术复杂度不让用户操心，但原理和逻辑链条清楚可查——像智能手机一样，操作极简，背后的道理说得通。
• 前台呈现层分层：校级看方向和全局，中层看过程和链条，教师看执行和任务。每一层只看到自己需要的信息。

2.3 评价链

在§2.2工作流程的"AI诊断"阶段，系统沿六层评价链逐层分析数据、运行诊断、输出结论。六层链条构成诊断的逻辑骨架：

定位层 → 结构层 → 解析层 → 执行层 → 结果层 → 验证层   ↑                                                        │   └──────────── 社会评价反馈，修订培养目标 ←────────────────┘ 

前两层是上游基础（回答"培养什么人"和"怎么分解到课程"），后四层展开为17项使命型指标。验证层的结论反馈回定位层，形成完整闭环。

第一层：定位层 —— 培养目标评价

这层回答的是最根本的两个问题：你在哪？（生态位）和凭什么是你？（差异化）。专业在学校整体布局和区域产业版图中的位置是否清晰？有没有自己的特色和不可替代性？如果定位模糊、与同类专业高度同质化，后续所有努力都会事倍功半。

评价培养目标时必须考量的五个维度：政策走向、行业趋势、学校基因底色、资源积累、学科支撑。当产业需求落在学科交叉点上时（如生物医药、艺工融合），还需评价专业能否打破壁垒、形成融合培养能力——即交叉性。

• 撰写指引/范本：系统提供范本 + 五维分析框架，帮助教师从五个维度审视培养目标
• 改进路径：定位层有问题 → 推送"培养目标修订模板"，引导重新对标五个维度

这层评价的核心是体系性——各教学环节是系统合力还是各自为战。教案、考核、学情分析、过程性评价……这些不是孤立的检查项，而是有机关联的整体。系统会检查它们之间是否相互支撑，能否产生"1+1>2"的涌现效应。

关键模板设计要点：
• 教案：不是讲稿，体现教师对每堂课的总体设计——讲什么、重点是什么、引入什么案例、与前序课程的逻辑递进、横向项目如何落地
• 考核分析：考核目的必须与教学目标对齐，考的是能力达成而非知识记忆
• 学情分析：纵向对比历届，为后续课程提供"交接棒"——"本课程学生哪些能力有基础/有短板"
• 过程性评价：填补"期末一张卷"与"能力达成"之间的断层。与终结性考核交叉验证：过程好+期末差→命题有问题；期末好+过程差→只考了短期记忆

分析撰写型的核心变化： 教师只需要回答"是什么"（培养目标文本、课程清单、考核方式、成绩数据），AI负责回答"怎么样"（支撑矩阵、覆盖率、一致性分析、根因追溯）。每个分析撰写型模板的字段分为两类：
• 教师输入字段：教师必须填写的原始事实
• AI产出字段：系统基于教师输入自动生成——教师提交后可查看但不可编辑，如需修正须修改输入字段后重新生成

3.2 核心原则：使命型为主

所有评价立足使命型，不是跳板，是目的地。 未来型扩展建立在使命型完全成熟之后。

3.3 逻辑主线：一致性 + 有效性

两套体系共享同一套逻辑DNA——一致性 + 有效性：

一致性回答"课程设什么方向"，有效性回答"教师能不能把这个方向的课教好"。

四、前台交互设计

核心原则：后台精准严密，前台极简易用，逐层展开按需触发。

4.1 四层界面

层级
用户看到什么
什么时候展示
第一层：首页
整体健康度结论 + 六层链条状态（红/黄/绿）+ 最大问题 + 最大亮点
始终展示
第二层：链条页
该环节下各指标的达标状态 + 趋势箭头
点击某层链条展开
第三层：发现页
具体问题的描述 + 证据链（引用原始数据）+ 根因标注
点击某指标展开
第四层：详情页
原始模板数据 + AI分析过程
点击证据展开，可追溯

游戏设计思路： 首页只给结论，想看细节就点进去，不看不干扰。管理者5分钟看完首页就知道整体状态。

4.2 逐层展开机制

用户进入系统 → 首页：整体健康度 + 一句话结论   ↓ 点击某层链条 链条页：该环节各指标红/黄/绿状态   ↓ 点击某指标 发现页：具体问题 + 证据链 + 根因标注   ↓ 点击证据 详情页：原始模板数据 + AI分析过程   ↓ 需要改进时 系统推送：改进工单 + 对应模板 + AI初稿 + 范本参考   ↓ 改进完成后 自动重评 → 追踪验证 → 偏离预警 

4.3 黑箱逻辑

AI处理层的复杂度不暴露给用户，但原理和逻辑链条要让用户理解——像智能手机一样，操作极简，但背后的道理说得通。

• 教师不需要知道AI怎么算的，但需要知道"为什么判定我的课程覆盖率不足"
• 管理者不需要知道算法细节，但需要知道"这个诊断结论的逻辑链条是什么"
• 每一层用户只看到属于自己的逻辑链条，不多不少
